总目录数据通路协同仿真延迟与性能

vdot微架构与数据通路设计

本文要点

  • VDot 以 8 路有符号字节乘法和三级加法树实现固定八项点积，内部总和为 19 位。
  • 数据通路在乘积和格式化结果处分别寄存，形成 FU 内部两拍流水；正常实例的输入到完成间隔为 2 周期。
  • 非零合法计算写入低 32 位结果并清高 96 位；合法 VL=0 通过 oldVd 保留完整旧目的。
  • VDot 挂接 VFEX0，复用向量源读取、控制流水和退休机制；源码摘录与示意图逐项对应。
  • 正数、正负边界、完整结果布局与旧目的保持检查均通过，代表实例与两拍设计一致。

1 对象

1.1 指令语义与实现约束

设计对象是自定义指令 vdot.vv 的 VDot 功能单元。硬件采用锁定香山版本的单核 MinimalConfig，VLEN=128；算术与控制行为依据项目 v0.1 合同。

表 5-1　VDot 的输入、结果和控制约束。

项目 约定 设计影响
运算输入 两个源寄存器的前 8 对 signed INT8 固定 8 路乘法，不随合法非零 VL 扩大项数
有效掩码 vm=1 取全部项；vm=0 使用旧 v0 的低 8 位 无效项的乘积置为有符号零
结果布局 低 32 位为有符号和，高 96 位为零 对完整 128 位目的形成确定结果
合法配置 SEW=8、LMUL=1，VL=0 或 8～16，vstart=0 权限和类型先检查，之后处理保持或计算
旧目的保持 合法 VL=0 时保留全部旧值 译码声明 oldVd 依赖，新物理目的仍需获得旧值
异常与取消 沿既有精确异常、恢复和退休路径处理 输出数据选择与架构状态更新分别控制

低 32 位布局、合法 VL 范围、掩码与状态策略属于 A01～A09 工程约定；当前实现按这些约定保持 RTL、NEMU 和测试一致。

证据：版本化语义合同 · 修复版源码与依赖清单

1.2 在整核中的位置

VDot 继承 VecPipedFuncUnit，以 VdotCfg 挂入 VFEX0。两向量源、旧目的、掩码和 VL 的输入需求由配置声明，既有调度和控制路径承担源就绪、ROB 身份以及物理目的传递。

实际 VdotCfg 配置如下。它声明执行单元需要的源类型、固定延迟和目的接口，是算术模块接入后端调度的入口。

  val VdotCfg = FuConfig (
    name = "vdot",
    fuType = FuType.vdot,
    fuGen = (p: Parameters, cfg: FuConfig) => Module(new VDot(cfg)(p)),
    srcData = Seq(Seq(VecData(), VecData(), VecData(), V0Data(), VlData())),
    piped = true,
    writeVecRf = true,
    writeV0Rf = true,
    latency = CertainLatency(2),
    vconfigWakeUp = true,
    maskWakeUp = true,
    destDataBits = 128,
    exceptionOut = Seq(illegalInstr),
  )

srcData 声明两个向量源、旧目的、掩码与 VL 的需求；writeV0Rf 支持目的为 v0；vconfigWakeUp 和 maskWakeUp 与相应源的就绪处理配套。CertainLatency(2)、destDataBits=128 与 VDot 类中的约束一致。

源码：FuConfig.scala

“FU 内部两拍”从输入接受到结果完成计量；从重命名到退休的时间还包含调度、依赖和按序退休等待。接口与异常信息通路详见整核集成报告。

2 方法

2.1 位宽推导与流水划分

八项和需要 19 位有符号数。 单项 signed INT8 乘积的范围为 −16,256～16,384，需要 16 位；8 项累加的范围为 −130,048～131,072。

表 5-2　算术层次与输出位宽。

运算层 数量 输出位宽 对应代码
有符号乘法 8 16 位 products，掩码筛选后送入 S1Reg
第一级加法 4 17 位 pairs
第二级加法 2 18 位 halves
第三级加法 1 19 位 sum
结果格式化 1 128 位 低 32 位符号扩展，高 96 位零，送入 S2Reg

以 a=[1,2,3,4,5,6,7,8]、b 全为 1、无掩码为手算例：乘积两两相加为 [3,7,11,15]，再得 [10,26]，总和为 36。此例说明加法树的组合关系；实际动态时序另见第 3.2 节。

2.2 算术源码与图示对应

以下摘录保存的 VDot.scala 第 15～23 行，代码保持原样。

  val products = VecInit((0 until 8).map { i =>
    val product = vs1(8*i+7, 8*i).asSInt * vs2(8*i+7, 8*i).asSInt
    Mux(srcMask(i), product, 0.S(16.W))
  })
  val p1 = S1Reg(products)
  val pairs = (0 until 4).map(i => p1(2*i) +& p1(2*i+1))
  val halves = (0 until 2).map(i => pairs(2*i) +& pairs(2*i+1))
  val sum = halves(0) +& halves(1) // 19 bits, including +131072
  val result = S2Reg(Cat(0.U(96.W), sum.pad(32).asUInt))
  1. products 对每个字节执行 asSInt 乘法，srcMask 为假时选择 16 位有符号零，对应图 5-1 的第 1 拍组合逻辑。
  2. S1Reg(products) 保存 8 个乘积；随后 pairs、halves、sum 依次形成三级加法树。
  3. +& 使每级和多保留一位；sum.pad(32) 进行符号扩展，Cat 拼接高 96 位零，S2Reg 保存最终 128 位结果。

正边界的低 32 位为 0x00020000。负边界的 19 位补码为 0x60400，符号扩展后的低 32 位为 0xfffe0400；两者的高 96 位均为零。

证据：VDot 源码

2.3 旧目的、异常与输出门控

合法 VL=0 仍需把旧目的内容传给本次分配的物理目的。 oldVd 用于保持路径，不参与非零合法计算的求和。译码保留旧目的依赖，执行端选择 outOldVd，保证后续退休得到原值。

以下为 VDot.scala 第 26～33 行。

  val illegal = outVecCtrl.vill || outVecCtrl.vsew =/= 0.U ||
    outVecCtrl.vlmul =/= 0.U || outVstart =/= 0.U ||
    (outVl =/= 0.U && (outVl < 8.U || outVl > 16.U))
  io.out.bits.res.data := Mux(outVl === 0.U || illegal, outOldVd, result)
  io.out.bits.ctrl.exceptionVec.get(illegalInstr) := illegal
  // Keep vecWen/v0Wen for legal vl=0: the new physical destination needs oldVd.
  // CSR updates and precise exceptions remain on the ordinary commit path.
  io.out.valid := fixValidVec.last && !outCtrl.robIdx.needFlush(io.flush)

表 5-3　末级数据选择与控制。

条件 数据选择 控制含义
合法非零 VL result 正常结果经 EXU 完成，并由后端安排物理写入与退休
合法 VL=0 outOldVd 保留完整目的值，合法完成的状态策略沿退休路径处理
局部非法状态 outOldVd 同时上报 illegalInstr，交给精确异常路径处理
流水有效位未到达或被取消 数据位不构成有效输出事件 io.out.valid 由 fixValidVec.last 与 needFlush 共同控制

向量权限及部分类型合法性在上游检查，FU 保留图示中的局部保护。若较老分支在物理结果写入之后才纠正路径，ROB 与重命名恢复阻止错误路径结果退休；输出门控不撤销已经发生的物理写入。

证据：控制接入说明

3.2 正常实例的两拍执行

正常 VDot 实例在 14220 ps 输入握手，在 14224 ps 完成，间隔为 2 个仿真周期。目标为 PC = 0x80000208、指令字 0x0220818b、ROB 1/36、pdest 62；输入、输出与后续退休通过同一动态身份关联。

表 5-6　波形关键读数。以 FU 输入沿为相对周期零点，仿真时钟周期为 2 ps。

信号或事件 读数 含义
FU 输入握手 14220 ps（+0 周期） 触发沿前输入 valid、ready 均为 1
FU 完成 14224 ps（+2 周期） 触发沿前输出 valid、ready 均为 1
动态身份 ROB 1/36，pdest 62 波形分别显示 ROB 1/0x24、pdest 0x3e
完整结果 0x000000000000000000000000ffffe900 低 32 位为 −5888，高 96 位零

14223 ps 的 Marker 位于输出触发沿前，此时输入 valid 已为 0；输入接受应读取画面左侧对应脉冲。该实例在 14272 ps 退休，相对输入为 +26 周期，体现了 FU 完成与整核退休的时间差。

证据：动态事件核验 · 第二阶段复现索引

4 总结与实验边界

VDot 已在固定配置下实现八项有符号点积、完整结果布局和两拍 FU 流水，指定算术检查、整核回归及正常动态实例与设计一致。oldVd、异常和取消通过执行单元与既有后端共同处理。

  • 配置：当前代码约束 VLEN=128、目的宽度为 128 位、latency=2；其他位宽或精度需要独立设计与验证。
  • 时间口径：图中 ps 是 VCD 的仿真标尺；FU 两拍、物理写入和 ROB 退休分别计量。
  • 控制验证：独立控制模块与正式 VecPipedFuncUnit 的接口行为分别验收；取消、CSR 和共享端口的覆盖范围见功能报告。
