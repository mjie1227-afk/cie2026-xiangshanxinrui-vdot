## 1. 官方要求与项目约定

已读正式材料明确昆明湖V2、SEW8、VLEN128，前8对signed INT8相乘后归约，初值0、不累加旧vd，一个结果写入目的向量寄存器、其余输出清零。[赛题正文](https://github.com/OpenXiangShan/XiangShanLab/blob/master/xiangshan-question-bank/8-xiangshan-development/development-question.md)；[官网语义原图归档](../artifacts/planning-2026-10-15/sources/official-semantics.png)。

题面没有完整定义下列边界，本文为可实施性给出确定的v0.1约定，并保留假设编号：

| ID | v0.1工程约定 | 依据/仍需保留的风险 |
|---|---|---|
| A01 | 结果用低32位补码保存，高96位清零 | 精确结果至少19位；32位是项目布局选择，不是官网明文 |
| A02 | SEW8、LMUL1；vl=0不写vd，vl=8～16只取前8对，vl=1～7非法 | 保留固定8对运算，不暗中变成min(vl,8)；合法范围属工程约定 |
| A03 | 支持vm=0/1，掩码逐对筛选乘积 | 参照常见向量源掩码方式；题面没有明确要求掩码行为 |
| A04 | 非零vstart非法；不支持在点积内部保存部分和恢复 | 参考标准归约规则，避免丢失前缀部分和 |
| A05 | 实际计算成功时按完整128位结果布局写入，不套普通tail/mask旧值合并 | 落实明确清零意图；与vl=0/异常的优先关系由本文定义 |
| A06 | 允许所有单寄存器源/目的重叠，包括掩码形式vd=v0；读旧状态后写新结果 | LMUL1便于明确；实现必须验证重命名、掩码依赖和写回 |
| A07 | custom-0、funct6=0、funct3=0、位25为vm | 当前源表静态检查无交叠，仍需生成译码/整核运行验证 |
| A08 | 所有合法完成（含vl=0）将相关向量VS状态置Dirty | 确定化项目策略，与当前NEMU整数归约路径一致；RTL必须匹配 |
| A09 | 初始开发沿用锁定V2谱系提交与单核MinimalConfig | 已有Hello/VADD基线可复用，尚未构建vdot版本；其他配置另验收 |

这些约定不应被包装成主办方批准。没有回复时可以用本文推进内部工程；若后续正式规则不同，按A编号定位影响并更新版本。正式赛题明确要求优先，不能为了测试方便改成dot4、16项点积或旧vd累加。

## 3. 指令编码

建议助记符为 `vdot.vv vd, vs2, vs1`，掩码形式追加 `v0.t`。助记符尚未加入工具链；初始程序可在后续实现时通过明确的机器码封装发射，不能直接假定现有汇编器识别。

| 位号 | 字段 | v0.1值/意义 |
|---|---|---|
| 31:26 | funct6 | 000000 |
| 25 | vm | 1无掩码；0用旧v0的逐位掩码 |
| 24:20 | vs2 | 向量源寄存器编号，0～31 |
| 19:15 | vs1 | 向量源寄存器编号，0～31 |
| 14:12 | funct3 | 000 |
| 11:7 | vd | 向量目的寄存器编号，0～31 |
| 6:0 | opcode | 0001011，即custom-0=0x0b |

```text
MATCH = 0x0000000b
MASK  = 0xfc00707f
is_vdot = (instruction & MASK) == MATCH

无掩码 vdot.vv v3,v2,v1       = 0x0220818b
掩码   vdot.vv v3,v2,v1,v0.t  = 0x0020818b
无掩码 vdot.vv v5,v2,v1       = 0x0220828b
```

识别MASK不检查vm和三个寄存器字段；这与执行用的v0数据掩码不同。vl、SEW、LMUL、vstart来自每条指令在程序顺序上应看到的向量控制状态，不编码到这32位里。结果低32位与指令编码32位是独立概念。

其他funct6/funct3位型不属于此vdot；由正常ISA译码处理，未分配时才报非法指令。不能把“翻转任意opcode位”都当成必须非法，因为它可能成为已有合法指令。custom空间及字段位置的规范依据见 [RISC-V opcode表](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv-32-64g.html)。

## 4. 合法性与优先顺序

先判断是否识别为vdot；以下步骤只作用于已识别的vdot。按顺序检查，不能先见vl=0就跳过非法状态：

1. 目标配置存在向量扩展，向量上下文可用；mstatus.VS不能为Off。虚拟化执行时，相关vsstatus.VS也不能为Off，沿用目标平台已有向量权限检查。
2. vtype合法：vill=0、保留状态合法、SEW=8（vsew=000）、LMUL=1（vlmul=000）。其他SEW/LMUL在v0.1中非法。
3. vstart必须为0；非零报非法指令，包括同时vl=0的情况。
4. vl只能为0或8～16；1～7非法。超过16是本配置不可达的非法/断言输入，不应通过偷偷截断接受。
5. 合法且vl=0：保留整个vd，按第7节正常完成；不进入数学计算或高位清零步骤。
6. 合法且vl=8～16：按第5节计算并完整写入128位目的结果。

所有被识别vdot的上述非法情况使用illegal-instruction异常（异常原因码2）。vd、所有源向量、vl/vtype/vstart/vxrm/vxsat不得由该指令写改；普通陷入机制更新异常CSR不在“保持”承诺之外被禁止。不要把异常当作正常完成清零vstart，也不要向ROB提交一个伪造零结果。

## 5. 精确数学与写回语义

先读取旧源和需要的掩码快照，再更新目的。元素0在源寄存器最低8位；元素i占bits[8i+7:8i]，只取i=0～7。每个字节按补码解释：0x00～0x7f对应0～127，0x80～0xff对应−128～−1。

```text
a = old vector register vs1
b = old vector register vs2
m = old vector register v0     # 仅vm=0时作为掩码依赖
sum = 0                       # 精确有符号累加，不加旧vd

for i = 0..7:
    if vm == 1 or bit(m, i) == 1:
        ai = signed_int8(bits(a, 8*i+7, 8*i))
        bi = signed_int8(bits(b, 8*i+7, 8*i))
        sum = sum + ai * bi

new_vd[31:0]   = twos_complement_32(sum)
new_vd[127:32] = 0
```

掩码使用v0的bit i，不是v0的第i个8位元素；只有低8个mask位参与。索引8～15的源数据、mask高位不影响结果，即使vl=16。vm=1不依赖v0的掩码值，但若显式vs1/vs2等于v0，它仍是普通数据源。

单项乘积范围[-16256,16384]，八项和范围[-130048,131072]。精确和至少19位（包含符号位），19→32位须符号扩展；没有饱和、舍入或截断数学结果。最终32位补码只是表示转换，不引入溢出。

例如−4写为 `0x00000000_00000000_00000000_fffffffc`，不能把符号位填满128位。vm=0且八个掩码位全0、vl>0时，sum保持0并将整个vd写零；这和vl=0保留整个vd不同。

## 6. 重叠、mask/tail与旧目标

- 所有向量寄存器v0～v31可作为数据源或目的，v0不是整数x0，不具有恒零属性。
- 允许vd==vs1、vd==vs2、vs1==vs2，以及vm=0时vd==v0。源和mask必须从写回前的架构版本读取；NEMU不得清零vd后再从与之重叠的源取数据。
- 对vl>0的合法执行，旧vd不参与求和也不参与目的高位合并；目的128位按第5节整体产生。
- vta/vma的0/1组合均接受，且不改变本自定义指令的完整结果布局。这是A05约定；不能把Mgu普通undisturbed/agnostic合并直接套到结果上。
- 对vl=0或异常，需要保留旧目标状态。即使不累加旧vd，微架构仍可能需要旧映射/旧目标依赖来实现保留；不能简单把新分配但未写入的物理寄存器提交成结果。

## 7. CSR、异常与取消

| 场景 | 目的向量 | 控制状态 |
|---|---|---|
| 合法vl>0，包括mask全0 | 完整128位写入 | vl/vtype/vxrm/vxsat不变；vstart=0；相关向量VS置Dirty |
| 合法vl=0 | 整个vd保持 | vl/vtype/vxrm/vxsat不变；vstart原本为0；按A08相关VS也置Dirty |
| 非法vdot | 不写任何结果 | 无vdot引起的上述向量CSR修改；按平台异常机制陷入 |
| 被分支冲刷/取消 | 不产生该指令的已提交结果 | 不提交该指令的CSR副作用或异常 |

A08选择保守的确定策略：合法完成时mstatus.VS置Dirty，虚拟化时同时使相关vsstatus.VS为Dirty，SD按架构规则反映。当前NEMU整数归约在vl=0分支也调用vp_set_dirty；RTL和参考模型后续必须对齐这一策略，不能仅因vl=0关闭目的写使能就漏掉独立的VS状态更新。精确点积不影响vxrm/vxsat，也不产生浮点状态/fflags副作用。

本指令不访存、不改变整数/浮点寄存器，不分支；正常完成顺序PC前进4字节。程序随后显式存储vd用于检查，不属于vdot自身访存。

归约不暴露部分和。实现可将中断留到完整指令边界，不能自行实现“从vstart开始并从零求和”的错误恢复。内部可以流水，但所有结果、ROB完整标识、物理目标和有效/取消状态必须对应同一动态指令。

## 8. 三方实现清单

| 组件 | 必须落实的内容 | 首轮验收 |
|---|---|---|
| RTL识别 | 自定义pattern、向量类别、源/目的类型、mask及配置依赖；核查前端预译码 | 同一word唯一命中vdot，其他原有指令不被抢占 |
| RTL控制 | 第4节异常顺序；合法vl=0保持；vset与vdot的控制状态依赖 | vl=0不绕过vill/VSOff/vstart异常，不能提交未写的新物理目标 |
| RTL计算/写回 | 精确signed乘积与求和；第5节全128位布局；重叠旧源；mask按bit | 结果和完整身份一致；不被通用MGU重新合并污染 |
| NEMU译码 | 顶层custom-0分派、vm及三个寄存器字段提取 | 区分识别vdot与其他指令；不只修改原OP-V分支 |
| NEMU执行 | 合法性检查、旧源/掩码快照、精确整数模型、CSR与异常 | 不从被清零的重叠vd中读取源；与RTL同一规格版本 |
| 应用/测试 | 机器码封装、实际控制配置、已知输入、完整16字节结果检查、异常检查 | 反汇编/机器码可定位；错误返回失败；保存退出码和原始日志 |

当前源码入口：`backend/decode/Instructions.scala`、`VecDecoder.scala`、`isa/bitfield/RiscvInst.scala`、`DecodeUnit.scala`、`VecExceptionGen.scala`、`UopInfoGen.scala`；FU分类/配置与实际执行包装器；NEMU的`src/isa/riscv64/instr/decode.c`、`rvv/`及向量状态布局。使用custom-0需要补isVecArith等OP-V相关识别，不能只加一行VecDecoder。精确实现路径在开发时再核对，不因本表已写就标为完成。

功能单元延迟、流水级数、每拍接受能力不在本版ISA语义中承诺。若拆成多个uop，仍必须提供与单条指令相同的架构结果、异常与取消行为；不得产生可见部分结果。

## 9. 测试预期矩阵

下表是完整指令的验收矩阵，**尚未在香山整核或NEMU执行**。软件模型与独立算术RTL的已覆盖部分见10-20验证记录，不提前勾选整核门槛。默认SEW8/LMUL1/vl8/vstart0、vm1，旧vd先填非零。低32结果之外一律按有效执行/不执行规则检查，不能只检查打印的一个整数。

| ID | 输入或场景 | 必须得到的结果 |
|---|---|---|
| T01 正数 | a=[1..8]，b全1 | 36，低32=0x24，高96=0 |
| T02 混合符号 | a=[1..8]，b=[1,-1,1,-1,1,-1,1,-1] | −4，低32=0xfffffffc，高96=0 |
| T03 最大和 | a/b均全−128 | 131072，低32=0x00020000 |
| T04 最小和 | a全−128，b全127 | −130048，低32=0xfffe0400 |
| T05 零/位置 | 全零；随后每次仅一个索引非零 | 零及对应单项乘积；每个0～7位置都测 |
| T06 后半部干扰 | 0～7同T01，8～15填127/−128；vl8与vl16 | 两种vl都得36，后半部不参与 |
| T07 普通掩码 | 同T01，vm0，v0低8位0x55 | 16；遍历256种低8位掩码时各有独立期望 |
| T08 掩码全0 | 同T01，vm0，v0低8位0 | vl8时整个vd为0 |
| T09 无掩码 | 同T01，vm1，v0为0 | 36；若vs1/vs2取v0，按其数据另算 |
| T10 vl0 | 合法状态，旧vd含非零高位 | 全128位保持；VS按A08置Dirty |
| T11 vl不足 | vl1、vl7 | cause=2，vd保持，不输出部分点积 |
| T12 配置非法 | SEW16、LMUL2/mf2、vill=1、VSOff | cause=2；分别覆盖vl0，检查非法优先于no-op |
| T13 vstart | vstart1或2，分别配vl0/vl8 | cause=2，原vstart不按成功路径清零 |
| T14 tail/mask策略 | 四种vta/vma，配T01/T07/T08 | 相同算术和完整布局，不残留旧高位 |
| T15 重叠 | vd==vs1、vd==vs2、全部相同、vm0且vd==v0 | 由写前源与mask快照算期望，结果不受实现读写顺序影响 |

| T17 控制 | 停顿/反压、连续输入、分支flush、复位 | 元数据/结果对齐；取消项不提交；采用真实接口支持的情形 |
| T18 相关回归 | Hello、VADD、既有乘法/归约 | 原有路径仍正确；不能通过关闭DiffTest绕过 |
| T19 编码 | vm/源/目标全组合、非vdot功能位型 | 65,536候选均识别为同一扩展；邻近位型不误识别；实际译码阶段另验收 |
